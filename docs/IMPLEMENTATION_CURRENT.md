## Схема

```text
Классическое хранилище 1С
        ↕ штатные команды 1cv8 DESIGNER
Существующая ИБ-посредник (уже подключена к хранилищу;
                          не ИБ проекта EDT)
        ↕ штатный XML 1С / временный импорт EDT
Штатный EDT Compare / Merge
        ↕
Существующий проект EDT + свой Git
```

При получении DESIGNER обновляет конфигурацию посредника, но не рабочий проект EDT. Его меняет **только штатный Merge по выбору разработчика**. При помещении (отдельная TEST-ONLY операция) штатный EDT-экспорт → XML во временную папку → Load в посредника → Commit в хранилище. Плагин не управляет историей пользовательского Git.

## Наблюдатель — есть и как работает [КОД]

`NativeEdtMergeChoiceObserver` подписывается на `IComparisonSession.IComparisonTreeListener`; по ID изменённых узлов читает в штатной `runComparisonTreeReadonlyTask` флажки, `MergeRule`, признаки вложенных исключений и `TopComparisonNode`. Дополнительно читает начальные настройки через `getNodesWithChangedMergeSettings()`. Узлы без различий `ComparisonFlags.hasDiffsMainOther()` отбрасываются — неизменённый дочерний `DoNotMerge` не означает, что пользователь оставил изменение локально. Нет побайтовой сверки `.mdo/.bsl/.distr` и нет собственного Merge.

**Сохранение результата:** после подтверждённого native Merge `Snapshot.classifyPending` сопоставляет FQN верхних EDT-объектов с идентификаторами изменений 1С из `PENDING`. Все соответствующие различающиеся узлы `[x] GetFromOther` → `accepted`; хотя бы один изменённый снятый флажок / `DoNotMerge` → `keptLocal`; отсутствие подходящего узла или неподдержанное правило → `unclassified`. `ReceiveCompletionRecorder.reviewedNativeObserved` записывает решения в `ReceivePendingStore`, снимает рассмотренные `PENDING`, повышает `REVIEWED`, **но не `APPLIED`**.

Принятое изменение снимает старые метки `KEPT_LOCAL/UNKNOWN`; сохранённое локально получает `KEPT_LOCAL`, неопределённое — служебное `unknown-choice-*`. Исторические `unknown-choice-*` не архивируются и не изменяются задним числом. Второй диалог выбора и прежнее диагностическое окно **отключены**; сведения наблюдателя остаются в Error Log.

**Зачем наблюдатель сейчас:** для записи решений текущего получения в локальный журнал. **Что не делает:** не управляет следующим Merge, не сравнивает код самостоятельно, не формирует исходящий список. Решения сохраняются **по идентификаторам изменения 1С**, а не по отдельным процедурам. Разные дочерние узлы одного `TopComparisonNode` могут быть ошибочно связаны с общей записью — это не испытано.

## Критически важное ограничение: следующий быстрый приём

**[КОД, изменения после `4fab919`] `KEPT_LOCAL` — новый обязательный триггер полной сверки.** При запуске быстрого получения плагин проверяет scoped `ReceivePendingStore.keptLocal` **до обновления ИБ-посредника**. Если записи есть, показывает сообщение о ранее оставленных локальных изменениях и предлагает «Полная сверка». Отмена прекращает получение без запуска обновления 1С; согласие переводит эту же операцию в полный native XML/EDT Merge, а не в выборочное `-getChanges`. При наличии `KEPT_LOCAL` быстрый маршрут не продолжается молча.

**После завершённого полного Merge и записи `REVIEWED`** выполняется пересмотр `KEPT_LOCAL` через штатные наблюдения отличающихся узлов EDT. **Область пересмотра ограничена** прежними `KEPT_LOCAL` и метками, созданными из реального `PENDING` текущего получения. Все остальные локальные изменения проекта не превращаются в `KEPT_LOCAL`. При полном наблюдении, если соответствующее отличие исчезло или все его узлы `[x] GetFromOther`, старая метка удаляется; при действительно оставленном локальном узле или неоднозначном правиле она сохраняется. При незавершённом наблюдении старые метки сохраняются без очистки. При отмене или неуспешном Merge пересмотра нет. **Пустой `KEPT_LOCAL` снова разрешает быстрое получение.**

Ограничение: текущий наблюдатель связывает вложенные узлы с идентификаторами по верхнему EDT FQN и ещё не испытан на смешанных решениях нескольких дочерних объектов одного владельца. При неполном снимке `KEPT_LOCAL` намеренно не очищается — повторная полная сверка может потребоваться. Повторный Merge и обновление ИБ не запускаются автоматически.

`KEPT_LOCAL` также **не считывается механизмом помещения**. `OutgoingReadinessCoordinator` и `OutgoingWholeObjectWriteCoordinator` проверяют `REVIEWED/PENDING`, а кандидаты к отправке выявляются отдельно через Git/native EDT compare. Учёт наблюдателя **не даёт списка процедур для отправки**. Это существующий пробел использования сохранённой информации, а не готовая возможность.

## Версии, безопасность и оставшиеся работы

`OBSERVED` — native HEAD хранилища; `SCANNED` — полный индекс посредника с привязкой к версии; `REVIEWED` — изменения версии рассмотрены; `APPLIED` — отдельно доказано полное применение; `PENDING` — ещё не рассмотренные изменения; `KEPT_LOCAL` — локально оставленный выбор; `UNKNOWN` — служебная неопределённость, не статус EDT. `REVIEWED` не равно `APPLIED`.

При `FullDump` в отчёте 1С полный источник требуется самой платформой; `changed=0` не означает отсутствие изменений. Быстрый маршрут не должен самостоятельно запускать полный Merge без согласия. Проверки Git, HEAD и неизменности посредника остаются обязательными; при отмене/неизвестном Merge нельзя очищать ожидания.

**Главный стоп-фактор помещения:** между LOAD и COMMIT нет независимой проверки фактически загруженных объектов и отсутствия воздействия на невыбранные. Даже после сборки **нельзя** считать исходящее помещение безопасным для рабочей ИБ. Не испытаны [?] новая запись решений observer → journal; смешанный выбор нескольких процедур; отдельные подчинённые объекты одного владельца; XML round-trip; добавление/удаление и конкурентные версии.

## Ручная очистка оставленных локально отметок (21.10.2026, код после `c90c5b2`)

**[КОД]** В `StorageSettingsDialog` → «Состояние синхронизации» есть кнопка **«Сбросить отметки о сохранённых локальных изменениях…»** и отдельный счётчик меток. Кнопка активна только при наличии сохранённого подключения, Git-ветки и непустого списка `KEPT_LOCAL`. Подтверждение сообщает количество записей и предупреждает, что прежние различия с хранилищем могут сохраниться, а быстрый приём перестанет требовать полного сравнения по этим отметкам.

`ReceivePendingStore.clearKeptLocalMarks` очищает **строго ключи `kept-*`** в scoped preferences одного проекта/хранилища/ветки/посредника. Перед очисткой проверяется, что набор не изменился с момента подтверждения. **Не очищаются** `PENDING`, `unknown-choice-*`, `REVIEWED/OBSERVED/APPLIED`, снимки, файлы EDT или Git. Удаление производится только после проверки текущей ветки, сохранённого источника и блокировки любых параллельных операций получения/помещения. При отмене ничего не удаляется.

Эта кнопка — сознательный *сброс локальных отметок*, **не доказательство** принятия старых изменений. Для их фактического объединения остаётся штатный полный Merge EDT. **[?]** UI и очистка не проверены в установленной EDT, сборка/CI не запускались.
