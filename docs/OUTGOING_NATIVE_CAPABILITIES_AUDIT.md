# Проверка штатных возможностей 1С для исходящей отправки EDT → классическое хранилище

Дата: 2026-10-18. Статус: **исследование, не готовая реализация**.
Не запускать реальный Lock, LoadConfigFromFiles, Commit или операции с
пользовательской ИБ до отдельной проверки совместимости и разрешения.

## 1. Что ДОКУМЕНТАЛЬНО подтверждено

### EDT: публичный экспорт объектов модели

В EDT SDK 2025.2 существует публичный интерфейс
`com._1c.g5.v8.dt.export.IExportService` с методом:

`IStatus work(EObject eObject, IExportArtifactBuilder artifactBuilder,
boolean exportSubordinateObject, boolean exportExternalProperties,
IProgressMonitor progressMonitor)`

Оба boolean явно управляют экспортом подчинённых объектов и внешних
свойств. `IExportArtifactBuilder` имеет штатную реализацию
`OrdinaryDirectoryBuilder.create(Path)`.

Ссылки:
- https://edt.1c.ru/dev/edt/2025.2/apidocs/com/_1c/g5/v8/dt/export/IExportService.html
- https://edt.1c.ru/dev/edt/2024.2/apidocs/com/_1c/g5/v8/dt/export/OrdinaryDirectoryBuilder.html

**Не доказано:** сигнатуры/работоспособность в фактической EDT 2026.2,
наличие нужных exporter'ов для каждого типа, полнота всех свойств и
ссылок, формат/количество файлов для независимого модуля, реакция на
составные типы, расширения и неизвестные ресурсы.

### Конфигуратор: выборочная ЗАГРУЗКА

Официальное руководство разработчика 1С 8.3, раздел 2.17.5.3
«Partial load», прямо подтверждает:

1. Частичная загрузка доступна в пакетном режиме Designer; можно
   загружать как объект метаданных, так и подчинённые ресурсы (модули,
   формы, Help и др.).
2. **Если выбран для загрузки весь объект метаданных**, его загружают
   целиком, с подчинёнными объектами. Неполный комплект файлов для
   существующих подчинённых ресурсов способен вызвать ошибку или
   значения по умолчанию, если связей нет.
3. Раздел 2.17.5.3.6 показывает явную загрузку ТОЛЬКО файла модуля
   `Catalogs/Counterparties/Ext/ObjectModule.bsl` через
   `/LoadConfigFromFiles ... -files <модуль>`.
4. Параметр `-partial` в справке пакетного режима задаёт частичную
   загрузку выбранных частей файлового представления; `-listFile`
   содержит пути файлов, а не имена объектов для захватов.

Источники:
- https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/
  (раздел 2.17.5.3.1–2.17.5.3.6)
- https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.27_Administrator_Guide/Appendix_7._Startup_command-line_options_of_1C_Enterprise/7.4._Running_Designer_in_batch_mode/7.4.4._Configurations_and_extensions/

**Важное различие**: `-listFile` для загрузки содержит пути
XML/BSL-файлов. `-Objects` для RepositoryLock/Commit — другой
формат и другая семантика.

### Хранилище: штатные захват и помещение

Документированы
`/ConfigurationRepositoryLock -Objects <file>` и
`/ConfigurationRepositoryCommit -Objects <file> -comment ...`.
Если **не передать `-Objects`**, операция может затронуть ВСЮ
конфигурацию, поэтому вызывающий код обязан запрещать пустой список.

Источник:
- https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.27_Administrator_Guide/Appendix_7._Startup_command-line_options_of_1C_Enterprise/7.4._Running_Designer_in_batch_mode/7.4.15._Configuration_repository_operations/

## 2. Что было моими ГИПОТЕЗАМИ, а не проверенными фактами

- «Штатный IExportService уже гарантирует готовые файлы, которые можно
  сразу частично загрузить в подключённый к хранилищу Конфигуратор».
  **Не подтверждено** реальным round-trip EDT 2026.2 → Designer.
- «Выборочный экспорт одного объекта автоматически правильно переносит
  типы реквизитов, включая `СправочникСсылка.Сотрудники`, и зависимости».
  **Не подтверждено**. Нельзя удалять/добавлять связанные объекты наугад.
- «При изменении модуля можно безопасно обойти описание документа».
  Designer умеет грузить BSL адресно, но получение корректного
  BSL-файла из EDT, требуемые захваты и отсутствие побочных изменений
  для нашей конкретной версии **ещё необходимо испытать**.
- «Отличие `configVersion`/UUID пары достаточно для бесконфликтной
  записи». Оно даёт признак изменения/замены, но не гарантирует
  совпадение исходной базы, отсутствие чужих захватов, сохранение
  ссылок и атомарность Commit.
- «Работает за десятки секунд». Нет замеров: даже один Designer-процесс
  в конкретной подключённой базе может запускаться заметное время.
- «Все виды объектов/форм безопасно проходят одинаковую загрузку».
  Не доказано: формы и их командные привязки уже давали расхождения.

## 3. Какие РАЗНЫЕ задачи надо проверить до записи в хранилище

**A — только модуль менеджера / объекта / общий BSL:**
найти штатный EObject или получить его родительский модуль из EDT;
экспортировать штатным EDT API во временную папку;
проверить фактически созданный путь;
адресно загрузить ровно модуль в ОТДЕЛЬНУЮ тестовую ИБ
с правильным `-listFile -Format Hierarchical -partial`;
сравнить содержание модуля и независимое описание объекта,
убедиться, что реквизиты/их типы и формы не изменены.
Только после подтверждения формата и поведения выбирать fast-path.

**B — изменён реквизит `Document.НачислениеПоСреднему.Сотрудник`
типа `CatalogRef.Сотрудники`:**
экспортировать штатное описание документа и подчинённые ресурсы
с флагами EDT SDK; проверить, что описание типа сохранилось, что
справочник существует под правильной идентичностью в целевой модели;
испытать загрузку в отдельной ИБ и сравнить после неё метаданные.
Нельзя утверждать, что экспорт одного BSL обновляет реквизиты.

**C — форма с элементами/командными привязками:** экспорт + проверка
повторной загрузки и соответствия модели; байтовый diff может быть
полезной диагностикой, но семантику 1С сам по себе не гарантирует.

**D — новая метадата, удаление, переименование, ссылки на отсутствующие
объекты:** отдельные проверки полного состава и зависимостей, запрет
удалять чужие объекты автоматически.

Эти тесты нужны **для квалификации транспорта**. Они не означают, что
должна запускаться новая тестовая ИБ при КАЖДОМ пользовательском
помещении одного уже поддержанного модуля.

## 4. Что НЕ делать

- Не подключать `OutgoingSelectedVersionCheck` напрямую как
  разрешение на Commit.
- Не считать результаты простого побайтового
  `OutgoingDeltaScanner` списком безопасной отправки.
- Не использовать ещё не проверенный `OutgoingStorageObjectsXml`
  для реального Lock/Commit без проверки формата и владения.
- Не включать новые команды записи, пока не проверены реальные
  модели и сигнатуры EDT 2026.2 и Designer целевой 1С.
- Не изменять файлы входящего механизма и не переподключать
  рабочую EDT/базу-посредник.

## 5. Статус

В ветке `feature/edt-to-storage-push` находится только экспериментальный
read-only каркас. Он **не умеет** реально экспортировать/загружать/
захватывать/помещать. Пока нет испытанного транспорта, не давать
его пользователю как готовый механизм. CI на этой ветке не запускался.
