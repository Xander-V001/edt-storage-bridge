# Пробный выборочный экспорт EDT → платформенный BSL

Дата: 18.10.2026. Статус: код добавлен в рабочую ветку, но не собран и не проверен в установленной EDT 2026.2.

## Новый проверяемый путь

После выделения в EDT Navigator существующих BSL-файлов одного проекта пользователь запускает пункт меню «Пробный экспорт выбранных BSL (без помещения)» и подтверждает операцию.

В фоновом Eclipse Job нативные сервисы EDT разрешаются через ServiceAccess без создания собственного Guice-инжектора. Читаются реальные FQN выбранных ресурсов, в BM read-only транзакции находятся top EObject, далее штатный IExportOperationFactory.createExportOperation с IExportStrategy.DEFAULT экспортирует платформенный набор XML/BSL во временную папку за пределами рабочего проекта.

Из этого набора формируются ТОЛЬКО кандидаты на частичную загрузку выбранных BSL-модулей. Их наличие в реальном выходе штатного экспортера проверяется; если отсутствуют, проверка завершается ошибкой. Полный экспорт объекта не трактуется как список загрузки.

Ограничение первоначального шага:
- src/CommonModules/<Имя>/Module.bsl → CommonModules/<Имя>/Ext/Module.bsl
- src/Documents/<Имя>/ManagerModule.bsl → Documents/<Имя>/Ext/ManagerModule.bsl
- src/Documents/<Имя>/ObjectModule.bsl → Documents/<Имя>/Ext/ObjectModule.bsl

Модули форм, макеты, изменения .mdo, новые/удалённые объекты и нераспознанные пути отклоняются. Списки объектов классического захвата и файлов частичной загрузки не смешиваются; реальный Lock/Load/Commit отсутствует.

## Почему пока запрещено помещение

Нужно вручную проверить совместимость OSGi/API на EDT 2026.2, фактические пути экспорта для одного CommonModule и Document, а также round-trip в **изолированной тестовой** базе на версии пользовательской платформы. Существующая база-посредник и рабочее хранилище не являются тестовыми объектами.

Следующие незакрытые задачи: происхождение непомещённых Git-изменений после входящего получения, корректное разрешение конфликтов, захват, адресная загрузка, независимая верификация результата, подтверждённый Commit и запись фактической ревизии.

Временная папка содержит исходный BSL-код; после ручной проверки удалять контролируемо. При неудаче смотреть локальный Eclipse Error Log. Ни Git-коммиты, ни содержимое проекта EDT не изменяются. CI и сборка не запускались.
