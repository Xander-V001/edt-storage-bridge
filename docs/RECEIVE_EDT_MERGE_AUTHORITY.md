# Штатное объединение EDT — единственный источник решения пользователя

Дата: 2026-10-19. Компонент: получение из классического хранилища в существующий проект EDT.

## Исправлено

При закрытии редактора сравнения EDT плагин больше НЕ вызывает
`VerifiedReceiveContent.verifyAndClear()`: функция сравнивала BSL/XML/бинарные
ресурсы байт-в-байт и сама снимала часть записей ожидания до подтверждения
разработчика. Это ошибочно считало результат native Merge незавершённым,
например при текстовых отличиях в 5 байт в длинном ManagerModule.bsl.

Вместо вторичного сравнения программа спрашивает, выполнил ли разработчик
объединение и завершил ли разбор ВСЕХ изменений, представленных в EDT.
«Нет»/отмена оставляет pending-список неизменным. «Да» означает принятие
результата штатного объединения, включая явно оставленные локальные отличия.
Побайтовый diff не входит в условие подтверждения.

После «Да» отдельная штатная проверка реального HEAD хранилища подтверждает,
что в ходе объединения не появился новый Commit. Только подтверждённая
ревизия позволяет снять ожидание по тем объектам, которые входили в открытое
сравнение. Непоказанные/отложенные объекты остаются pending; пока они есть,
нельзя отмечать ВСЮ ревизию как рассмотренную. Если реальный HEAD не
определён или изменился, подтверждение EDT показывается, но pending не
очищается, версия не придумывается. Не устанавливать полную байтовую
идентичность с хранилищем, когда пользователь сохранил собственный код.

## Ограничения

- Редактор EDT предоставляет штатное объединение, но обычное событие
  закрытия окна Eclipse само по себе не удостоверяет, что пользователь
  нажал «Объединить». Поэтому необходимо явное подтверждение.
- Аутентификация актуальной версии хранилища остаётся независимой
  проверкой, не проверкой BSL. Если текущая операция не имеет достоверной
  привязки снимка к номеру ревизии, отметка обработки откладывается.
- Ранее потерянное состояние или старые pending нельзя автоматически
  объявлять завершёнными без нового подтверждения пользователя.
- Код не собран и не проверен на фактической EDT 2026.2. Автоматическая
  сборка запрещена; ручная — только по отдельному разрешению.

## Контрольные тесты

`EdtMergeAcceptanceTest` проверяет: принятие всех показанных ресурсов
без сравнения текста BSL; отказ при закрытии/отмене; запрет списания без
подтверждённого HEAD; сохранение не показанных в EDT объектов в pending.
