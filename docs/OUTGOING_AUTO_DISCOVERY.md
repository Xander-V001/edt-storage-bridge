# Автоматическое определение изменений EDT → хранилище

Дата: 2026-10-18. Реализовано обнаружение кандидатов, НЕ реальное помещение.
Код не собран и не испытан в EDT 2026.2.

Команда ручного выбора BSL удалена из интерфейса. Существующая команда
«Проверить возможность помещения в хранилище» проверяет Git HEAD, читает
последнюю ревизию 1С и сверяет обработанную входящую ревизию. Если требуется
получение — предлагает уже существующий механизм.

После подтверждения актуальности для автоматической области должен существовать
контрольный Git SHA **последнего успешно помещённого** состояния. Он привязан к
EDT-проекту, хранилищу, базе-посреднику и пользовательской Git-ветке.
Его запрещено автоматически подставлять из HEAD, HEAD~1 или результата
получения. Пока native Commit не реализован, такая контрольная точка
обычно отсутствует — UI честно сообщает, что определить список надёжно нельзя.

При наличии доверенной точки проверяется ancestry SHA → HEAD, затем читается
совокупный Git diff по src через --name-status --no-renames -z. Учитываются
добавления, изменения и удаления, в том числе BSL, формы, .mdo и другие
метаданные. Имена группируются по EDT-объектам через EdtPathObjectMapper.
Неопознанные пути, смена HEAD, отсутствующая ancestry блокируют подготовку.
Ручного выбора объектов нет; Git-ветки и индекс не меняются.

**Ограничение:** этот diff содержит возможные изменения, ранее полученные из
хранилища, а не только разработки пользователя. Требуется отдельный этап
достоверного разделения происхождения изменений и проверки модели. Сейчас
это лишь кандидаты, недопустимые к Lock/Load/Commit. Не следует объявлять
их готовым составом помещения.

Будущая запись confirmedPublishHead разрешена только после фактического
Commit и независимой проверки новой ревизии 1С. В текущем исходящем пути
такой записи нет. Реальные база-посредник и хранилище не изменяются.
