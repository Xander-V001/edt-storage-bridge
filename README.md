# EDT Storage Bridge

**Текущее описание проекта — 20.10.2026.** Плагин для **1C:EDT 2026.2** и классического хранилища конфигурации 1С. Работа ведётся в ветке `feature/edt-2026.2-integration`. Репозиторий с кодом плагина **не** является Git-репозиторием пользовательской конфигурации.

> **Статус:** исходники получения (быстрое и полное сравнение) и экспериментального помещения существуют. Успешная CI №65 относится к `494ff6b`, а ветка позже дошла до `931c846`. Последний HEAD **не имеет подтверждённой успешной CI**, а end-to-end корректность на реальном EDT/1С **не доказана**. Сборка ≠ испытание. Не выдавать TEST-ONLY помещение за промышленно готовую функцию.

## Участники и границы

- Одно существующее классическое хранилище 1С.
- **Уже существующая** база-посредник, подключённая к этому хранилищу, **не подключённая к EDT**. Ни одна произвольная ИБ проекта EDT не должна становиться посредником.
- Существующий проект EDT со **своим** Git (`main` и пользовательские ветки задач); плагин не делает reset/rebase/checkout/auto-commit.
- Платформенный `1cv8 DESIGNER` — транспорт обновления посредника, XML и операций хранилища. Нативные EDT API — преобразование, сравнение и Merge.

## Пользовательские операции

- **«Получить изменения»** — инкрементальная выборочная подготовка с сохранением непринятых изменений. При проблемах совместимости источника допускает явное, а не скрытое, полное сравнение.
- **«Полная сверка с хранилищем»** — обновляет посредник по явному подтверждению, получает полный XML, формирует временную EDT-модель и открывает глобальное сравнение/Merge.
- **«Проверить возможность помещения в хранилище»** — проверка/подготовка просмотра. Из просмотра при дополнительных подтверждениях доступен **тестовый, реально записывающий** whole-object путь Lock → Load → Commit; **только на изолированных копиях**.
- **«Проверить версию хранилища»** и **«Очистить историю получения…»** — чтение нативного HEAD и контролируемая архивация/сброс локального состояния соответственно.

## Аналог 1С:ГитКонвертер — что именно заимствовано как идея

[1С:ГитКонвертер](https://github.com/1C-Company/GitConverter) обеспечивает **односторонний** перенос хранилища 1С в Git/EDT, поддерживает инкрементальную выгрузку и историю. Наш плагин **не копия его исходников и не исполняет его конфигурацию**: он использует тот же **принцип нативной выгрузки изменений платформой**, затем передаёт результат **в уже открытый проект EDT через штатный Merge**, не создавая чужую Git-историю. Обратное помещение — отдельная собственная TEST-ONLY реализация. Точный транспорт описан в документации, а не приравнивается к 1С:ГитКонвертеру.

## Дисциплина

Без отдельного разрешения не запускать сборки/CI, рабочую ИБ, хранилище, EDT и VPS. Перед любой реализацией читать [AGENTS.md](AGENTS.md), текущую ветку и перечисленные контракты. Ни один из этапов не должен помечаться успешным только по exit code 0, закрытию редактора или совпадению цифры версии.
